# v05 操作指南 · 图片本地调用，视频分段生成

更新：2026-11-18。执行[共同点亮剧本](01-FULL-SCRIPT.md)、[分镜](02-STORYBOARD.md)与[分段计划](05-GENERATION-PLAN.md)。用户已确认会员开通；本指南不假设开通后所有模型都免费，也不把旧Mini样片视为Seedance2.5已验证。

## 1. 本轮基线与素材准备

已生成4秒Mini试片（94积分，彼时余6积分），见[试片记录](LIBTV-TRIAL-20261118.md)。用户认为样片可用；跑步偏差、接缝和水印仍记录为后续改进项。另有三张2048×1152的GPT Image2图：局部空舞台、Jessica首帧、Feng首帧，用户已接受作为下一阶段参考。详见[图像流程](DREAM-PAINTER-WORKFLOW.md)。这三图只确认局部构图，不等于最终Logo全景已成立。

六人角色不重画；Wei＝Renwei。现有三视图用于检查侧背角度，不把三视图拼板当视频首帧。图片按缺口使用dream-painter多图编辑，先固定空间再插人物；每次保留输入顺序、实际Prompt、模型部署、尺寸和结果。新素材使用版本号，不覆盖已认可母图或旧实际日志。

在LibTV新画布或现有画布中按“角色 / 舞台 / A–E段 / 已选结果”整理。逐段使用`SEG-B_v01`等版本名；本次文档更新不启动任何收费生成。

## 2. 先生成B段8秒：Jessica → Feng

1. 导入Jessica、Feng原单人图和HANDOFF三张新图。原单人图约束身份，新人物图约束各自构图，空舞台约束材质与机位。素材数量超过面板上限时先查看支持方式，不能默默丢掉某个角色引用。
2. 选择LibTV **Seedance2.5 / 全能参考**作为主测方案。查看当前会员的时长、分辨率、数量、音频与报价；目标8秒、16:9、1个、关闭音频，尽量原生1080P。若参数不支持目标值，选最近更长时长，在实际Prompt写明额外时间保持末态，记录真实参数。Flash仅用于明确需要的预演或对照。
3. 打开[SEG-B提示词](prompts/SEG-B-video-v05.txt)。`【JESSICA】`等只是模板别名；逐个从页面的`@`菜单或参考缩略图旁的`@`按钮插入平台标签，替换别名。不能只手打@人名冒充绑定。确认每个标签对应正确缩略图。
4. 保存实际展开后的Prompt到`actual-prompts/SEG-B-video-v01.txt`，再核对报价并启动一版。下载原始结果到`raw-video/SEG-B_v01.mp4`，填写`run-log.csv`；未采用则标`no`，不能把计划文本列为已使用。
5. 连看并检查：前4秒Jessica清楚认脸，4–6秒短侧步与近景遮挡，6–8秒只出现Feng并接光站稳；无跑步、融脸、随机人物、完整Logo提前曝光。构图参考不等于面板锁定首帧，照实际使用的模式记录。

B段若失败，先简化动作与遮挡；仍串脸再在完全遮挡处分成两次任务。只重做失败部分，不退回全片12次零散生成。

## 3. 尽早验证六人和Logo高风险段

先用dream-painter制作16:9高分辨率空舞台全景`STAGE_MASTER.png`，保持原Logo拓扑、交叠与中心留白。以同一底图和六位角色制作`GROUP_MASTER.png`：Feng前排中央，Jessica第二排左、Scott第二排右，Song/Amy/Renwei第三排从左到右。六人脚都落在可见实面，彼此不遮脸。

从同一空间母版派生低位群舞局部`GROUP_LOCAL.png`，不要独立生成一套不相关的舞台角度。先检查它和全景的站位及几何能否衔接；没有三维依据的多视图仍是视觉参考，不能声称精确重建。

正式E段12秒使用D段已选末帧与同一GROUP_MASTER；D尚未生成时，可以用GROUP_LOCAL做E段技术预演，明确标记预演，正式接片仍需匹配D的真实末态。

E的0–4秒为连续升高后退，4–12秒完整Logo持续可见并真实群舞。**GROUP_MASTER是第4秒到达的构图，不是整段第12秒的尾帧。** 若面板只能锁首尾帧或模型把揭示拖到最后，拆成E1的4秒揭示与E2的8秒群舞，以实际末帧衔接。首尾帧模式只有实际启用才记录为锁定。

Logo漂移时，可将D末镜与E前4秒统一改成同一高清全景母版的局部裁切→二维拉远，人物和背景作为整体缩放，记录真实制作方式。E后8秒仍必须有六人舞蹈。多人复制或串脸时按六人分别同机位生成并分层合成；不能省人、换随机脸，或以静态图代替整个舞段。

## 4. 锁音乐，再补C、D和A

以[MUSIC-main](prompts/MUSIC-main.txt)生成一首原创纯器乐电子Funk；优先查看LibTV是否具备实际可用的纯音乐模式，没有时使用合适的音乐工具。先临时120BPM节拍验证，尽早锁一条音乐；实际BPM需检测，不把Prompt中的数值视为结果。

音乐结构：0–4秒第一拍与脉冲；4–20秒逐层加入贝斯/切分；20–24秒三人共振稍停；24–36秒伙伴接续并蓄力；36–40秒减薄；40秒强拍点亮，持续至48秒；48–60秒尾奏，最后1秒淡出。少量落脚和光流whoosh在后期对拍加入，所有视频随机原声先静音。

参照[五段计划](05-GENERATION-PLAN.md)制作C12秒、D12秒、A4秒。C保持Feng→Scott→三人，D保持Song/Amy→Renwei→六人。允许明确的动作匹配切镜，不把12秒写成强制一镜到底。仅暴露当段当时应出现的人物，尤其不能让多人参考图造成提前露脸。

## 5. 精确剪辑、片尾与导出

主轨按A4＋B8＋C12＋D12＋E12＝48秒拼接，使用[generation-timeline.csv](generation-timeline.csv)；[edit-timeline.csv](edit-timeline.csv)保留12镜的逻辑边界及段内目标入出点。模型实际时间偏移就重选、微调或补镜，不能假装自动剪辑已严格执行。LibTV智能剪辑可试，若无法精确多轨编辑则下载到剪映等编辑器完成。

共同检查：光始终由动作触发，0–36秒只见局部，36–40秒靠视野揭示既有结构，40秒共同点亮。人物可辨性始终优先；过曝、粒子遮脸、换景和Logo变形不算电影感。全景最后8秒保持可读且有真实舞蹈，末尾只短暂停格。

片头后期叠加完整团队名`STCA M365 Copilot Foundation & Platform Team`与`FY27 KICKOFF`。48–52秒实际制作信息，52–60秒实际采用资产的完整原始Prompt分页。`credits-info.json`按真实采用工具填写，实际记录就绪后运行`python production/make_credits.py`，查看生成的卡片与时间表再放入时间线。历史素材来源Prompt也需记录；试制但未采用的图不能冒充成片来源。

全文Prompt仅暂停可读，仍需按活动方口径确认接受程度。最终MP4/H.264、1920×1080或更高、16:9、30fps、60秒/1800帧；音频AAC。480P素材导出1080P不等于原生高清，保留真实尺寸记录。独立播放器完整看一遍，再按[验收表](04-DELIVERY-CHECKLIST.md)检查。交付视频、实际Prompt文本与必要制作信息，保留源片和剪辑工程。
