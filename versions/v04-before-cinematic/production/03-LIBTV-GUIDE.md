## 6. 生成一首贯穿全片的 AI 音乐

1. LibTV 画布新建音频节点，查看模式与模型。选择明确支持 **背景音乐／纯音乐生成**的模式；不要选纯 TTS 配音。
2. 复制 [MUSIC-main.txt](prompts/MUSIC-main.txt)。有独立歌词框则留空，有“纯音乐／Instrumental”开关就开启。长度可选时选60秒或更长；不可精确指定时生成较长歌曲，剪出结构完整的一分钟。
3. 生成2个候选，选无唱词、鼓点清楚、风格持续一致的一首，下载 `audio/BGM_original.wav` 或平台原生音频格式。不要把每个镜头的自带音乐拼起来。
4. 若只有音效／配音能力，切到 [Suno](https://suno.com/) → Create／创作 → 自定义模式 → 纯音乐，粘贴同一音乐提示词到风格描述；生成后从自己作品的下载入口下载音频，再导入 LibTV或剪映。平台套餐与下载权益需按当前账户确认。
5. 导入剪映，把音频放在 **0–60秒**。使用音乐节拍／自动踩点功能标记鼓点；没有此功能就放大波形手动每2秒标一处，并试听验证。提示词写120 BPM不等于文件严格120 BPM。
6. 若实际 BPM 与120接近，以音频变速（尽量保持音调）校正：速度倍率＝120÷实测BPM。例如实测118则约1.017。先试听，不接受明显音质损伤；否则换候选。保留未经修改原文件。
7. 若选用歌曲结构与提示词不完全一致，在音乐的小节边界拼接：0–4秒用稀疏前奏，4–32秒稳定主段，32–40秒上升或主段渐强，40–48秒高潮，48–60秒器乐尾奏并淡出。复制乐句时使用很短音频交叉淡化，试听不跳拍；不要在鼓点半拍处乱截。
8. 将0–48秒音乐设为正常响度，48秒后降低约6–9 dB，最后1秒淡出。所有视频片段原声先静音；需要滑行whoosh与踏步音效时只加少量，落在8／10／20／36／40秒等关键切点，不盖过音乐。

**应得到：** `audio/BGM_final.wav` 或剪辑工程中完整60秒音乐轨，清楚记录AI生成工具与实际Prompt。音乐许可和下载权益按所选账户实际条件核对。

## 7. 制作片尾与完整 Prompt 页

### 制作信息卡：48–52秒

深蓝底，留安全边距，1080P下主要文字建议36–48px，内容示例：

```text
原来，我们一直在 Copilot 上
STCA M365 Copilot Foundation & Platform Team
FY27 Kickoff
导演／主创：Baoli Wang
图像：[实际模型]  视频：[实际模型]
音乐：[实际模型]  剪辑：LibTV／剪映（按实际填写）
```

上面方括号必须替换；未用的工具不署名。不让视频模型生成这些字，使用编辑器文本或下方工具排版。

### 全部原始 Prompt：52–60秒

1. 为最终采用的每个AI资产留一条生成记录；重复使用同一资产只列一次，改过提示词则记录真正生成该版本的全文。
2. 范围包括：本次首帧、视频、音乐，以及采用的既有角色母图／舞台图的来源Prompt；可直接引用项目 `prompts/` 下已有文件。既有单人母图的模型名若生成日志未记录，先核实原配置／生成记录，不根据API环境变量猜模型。
3. 复制实际文本到 `production/actual-prompts/`。在 `run-log.csv` 中填写 `actual_prompt_file`，路径相对于 `production/`，例如 `actual-prompts/S03-video-v01.txt`；既有来源可用 `../prompts/...txt`。输入、输出文件同样写路径便于追溯。
4. 填写 `credits-info.json` 的真实工具信息，然后在本机 PowerShell（不是网页输入框）从项目根运行：

```powershell
python production/make_credits.py
```

依赖 Pillow；若提示缺失，在本机终端运行 `python -m pip install Pillow`。工具按实际日志合并去重，生成全量文本、1080P无截断Prompt分页卡、制作信息卡，以及精确8秒的卡片时间表。信息未填或没有实际Prompt时会停止，不生成“实际已使用”的假片尾。

5. 把 `production/credits/cards/` 中的图片导入剪映：`credits-info.png` 放48–52秒；其余按 `production/credits/card-timeline.csv` 放52–60秒。按照表中帧数设置长度，不使用默认每张3秒。时间线帧率为30fps。
6. 正常播放可读的是制作信息与“原始Prompt／可暂停阅读”标题。原始全文只能暂停或逐帧阅读；逐卡检查文字能在1080P静帧中读清，且没有漏页、裁切或占位符。
7. 附件交 `production/credits/ACTUAL-PROMPTS.txt`、`run-log.csv` 和实际提示词文件。附件是补充，不冒充已在视频里展示。

若活动要求“正常播放逐字读完所有原始 Prompt”，在提交前需获得延长附录或附件替代的允许。本指南没有把该解释问题视为已解决，也不会通过极小字或二维码规避。可先完成主片与暂停可读版，等待明确交付口径。

## 8. 精确剪辑成60秒

1. 剪映新建项目 `FY27_Focus_Kickoff_final`，画幅16:9。导入12镜已选MP4、完整音乐、片尾图片。
2. 把 S01–S12 顺序放主轨，先全部静音。按 [edit-timeline.csv](edit-timeline.csv) 设置每镜长度：**4、4、2、2、4、4、4、4、4、4、4、8秒**。总计48秒。
3. 放大时间线，在0、4、8、10、12、16、20、24、28、32、36、40、48、52、60秒作标记。调整每段的源片入点以对准动作，保持这些边界不动。
4. 音乐从0秒开始铺到60秒；鼓点与切口对齐。舞蹈若差半拍，可小幅变速约0.9–1.1倍并重选入点；出现夸张快慢或仍不合拍就重生成该镜，不拖坏整条音乐。
5. 在0–4秒叠加正式团队名“STCA M365 Copilot Foundation & Platform Team”和“FY27 KICKOFF”；团队名建议分两行：`STCA M365 Copilot`／`Foundation & Platform Team`，不缩写；可加片名，不能盖住鞋与光纹。1080P中文字至少36px，离画面边缘至少80px。名字条可选，姓名未确认不加。
6. 40–48秒完整Logo持续可见；46–48秒可叠加团队名，保持标志轮廓和人物不被文字遮挡。
7. 48–52秒制作信息卡，52–60秒Prompt分页卡；将最后一页延到严格60秒的结尾。不要在最后再加软件默认片尾。
8. 检查全片是否恰好 **60.000秒／1800帧（30fps）**。若有转场使总长缩短，优先删除叠化或在同镜源片余量中补齐，不能把Logo8秒缩掉来凑数。

### 如要在 LibTV 内剪辑

官网更新记录确认：把多个视频连接到画布的 **视频剪辑** 节点，可添加文字、音效与背景音乐。可以先选该节点，将12镜和音乐连入，要求“严格按镜号和CSV时间硬切，视频原声静音，不重写故事，不随机换片，最终60秒”。随后逐段检查时间线、音轨和字幕。

若当前节点不能逐段设置源入点、精确卡片帧数或多轨遮罩，就逐镜下载，回到上述剪映步骤。不要因为平台称为“一站式”就假设它已正确执行精确时间表。

## 9. 导出与交付

1. 导出格式 **MP4**，编码 **H.264／AVC**，尺寸 **1920×1080**，帧率 **30fps**；码率建议12–20 Mbps、音频AAC 48kHz且有足够码率（如192kbps或以上）。若导出界面只提供“高／推荐”，先选高，再检查成片。
2. 文件名 `FY27_Focus_Kickoff_Baoli_v01_1080p.mp4`，保存至 `production/exports/`。1080P宽高必须在播放器文件属性中核对，不只看导出按钮文案。
3. 如果原片为720P，导出1080P只改变尺寸，不自动增加细节。需先用平台或编辑器的超分能力处理并检查脸／Logo，再记录原始分辨率；能重生成原生1080P则优先重做。
4. 用独立播放器完整看一次声音与画面，再逐帧看接力切口、六人群舞、Logo揭示和所有Prompt页。确认无黑帧、水印误用、默认片尾、占位符、脸部互换、人物复制。
5. 对照[提交验收](04-DELIVERY-CHECKLIST.md)，交MP4、全量实际Prompt与必要制作信息；剪辑工程留本地备份。活动上传位置与最新截止通知以组织方信息为准。

## 10. 常见失败的具体修复

### 单人变脸／双人或三人串脸

先回到静态首帧，分别检查左右角色；不合格首帧不继续生视频。用正面单人图代替多人总览／带标题参考板；将转身改为侧看，取消交叉走位和互相遮脸。仍串脸时在同机位分别生成每个人的舞蹈，再按下面绿幕路线合成；S07必须保留Feng前排中央、Jessica左后、Scott右后的核心三人同框。不能通过更换脸型或省掉同框解决。

### Jessica 滑出却变成 Feng

拆为 S03、S04 两次任务，各自只一位人物；禁止在单条Prompt要求“人物从Jessica变成Feng”。在遮挡或强拍处剪接，方向统一向右。若滑行无法完成，缩短为舞步中的一小段侧滑，保留彩光与跟拍，不改成大幅飞跃。

### Logo 随镜头变形／升镜无法在4秒完成

先试首尾帧模式，固定同一站位的起止图，降低人物动作幅度。仍不稳定时使用 **高位局部裁切→全景拉远**备选：以同一高清六人全景为场景基准，把S10改为该视角的局部裁切，S11在4秒内从局部连续缩回全貌，S12保持全景。此方案靠镜头拉远揭示既有Logo，保留故事反转；它是后期二维拉远，不再宣称真实三维升降运镜。尽量用高于1080P的母图以减少放大模糊。

### 六人消失／复制／脸串换：分层合成路线

1. 保留 `STAGE_MASTER.png` 为空舞台背景；按六位角色分别做同一高位视角的单人首帧。每组人物朝向、光线与全景站位一致，背景换为均匀纯绿，无绿色反光、无阴影渐变。
2. 每位单独图生视频，固定机位、只做原地踏步和开手，不侧滑出范围；S10每位至少5秒、S12每位至少10秒。沿用同样动作节拍与相机视角。
3. 剪映把空舞台放主轨，六条单人视频作为六层画中画放上方。逐层选择“抠像→色度抠图／绿幕”，取绿色并调整强度和边缘到背景干净但衣服不缺损；深蓝队服通常有利于与绿背景分离，袖口绿色附近仍需检查。
4. 缩放、移动到 `GROUP_MASTER.png` 已规划的六个实面站位；必要时轻微旋转与透视匹配。将母图临时叠在最上方、透明度降到约50%，对齐脸、脚和相对位置后隐藏母图。脚底必须落在实面。
5. 每位统一在同一拍开始动作，调整源片入点；S10仅Renwei在第三排右侧做很短入场，其余五人已就位。各层只一份，数清六人，保持1＋2＋3队形。
6. S10／S11／S12使用同一套舞台和人物图层位置。若用上面的二维拉远方案，将所有背景与人物层一起建复合片段，在S11对复合片段做相同缩放／位置关键帧，禁止只缩背景而人物不动。
7. 导出这三镜的合成素材再回主时间线；S12必须保留实际舞蹈运动。静态全景只能用于首帧或极短定格，不能代替8秒群舞。

分层会牺牲一点原生三维镜头的自由度，但保住六人身份、舞蹈运动和固定Logo。绿幕边缘或透视不合格，就重做该组同机位素材，不把不一致当成“AI风格”。

### 文件够长但动作来不及／音乐不合拍

先微调源入点；动作超过分配时长则简化为一个踏步与开手，把转场放乐句末尾。生成片长与成片片长分开管理，不能把所有5秒源片直接拼成65秒。音乐先锁定一条，再剪动作，不为每镜换曲。

### 片尾实际Prompt太多

由工具自动分页，不能缩到不可读的小字。若每页少于3帧，工具会报错，需要改变片尾方案或取得更长附录许可。即使页数少且可暂停阅读，也不代表正常速度阅读要求已满足。
